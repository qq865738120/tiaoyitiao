## 工程与目录职责

Creator 3.8.8，TypeScript，已有 Game Agent 0.4.0。原资产固定在 `assets/resources/jump`。目录职责如下，按阶段创建；已有实现以交接记录为准：

```text
assets/scenes/JumpMain.scene
assets/scripts/jump/core/       # 无 cc 依赖的规则、种子、状态、落点、计分
assets/scripts/jump/adapters/   # Creator 输入、音频、存储、时钟
assets/scripts/jump/view/       # 角色表现、平台视图、相机、HUD
assets/scripts/jump/app/        # GameBootstrap，组装和生命周期
assets/prefabs/jump/            # 角色、平台包装、UI
assets/materials/jump/          # Creator 中制作的材质副本
tests/jump/                    # 纯逻辑与回放测试，放在 assets 外
docs/交接记录/阶段NN.md          # 本工程实际实施与证据
docs/验收证据/                 # 后续截图、录像、结果，逐工程独立
```

每个模块首次修改前补 README。不要修改插件源代码、其他工程、原始参考 JS、基础素材哈希或项目身份。不要把整个 resources 目录全部预加载；仅通过白名单引用本阶段需要的资源。本任务在Creator预览中完成，不要求打包构建或发布，也不删除备用素材。

## 跨阶段接口

| 契约 | 数据/职责 | 验证要求 |
| --- | --- | --- |
| GameConfig | 版本、seed、物理/计分/平台/时间参数 | 对照设计文档；参数只有一个权威来源 |
| PlatformSpec | id、centerXZ、topY、rect/circle、halfExtent/radius、modelKey | 不从阴影包围盒猜碰撞 |
| RunState | runId、phase、tick、score、streak、currentId、targetId | 纯状态迁移；旧 runId 事件无效 |
| JumpPlan | jumpId、起点、方向、startTick、distance、flightTime、目标 id | 飞行中不可被视觉缩放改写 |
| DomainEvent | Started/Charge/Jump/Landed/Scored/Failed/Paused | jumpId 去重，表现层只消费事件 |
| ReplayRecord | configVersion、seed、[{tick,type,source}]、结果序列 | 同输入可跨帧率比较；不记录用户资料 |
| AssetCatalog | 当前工程的 Prefab/Texture/SpriteFrame/AudioClip 引用 | 查询 Creator 子资源，禁止猜 GLB URL |

测试配置、回放格式和事件类型在阶段 01 定义；在阶段02补全，不通过不透明修改数值来适配失败的视觉模型。碰撞只使用约定几何范围，不交给不确定物理刚体弹跳。

## 每阶段的共同执行流程

1. 确认当前工程路径/UUID/Creator 版本，读本阶段与前置交接记录，检查素材基线。
2. 查询 Game Agent 当前可用工具和 Schema，按 Creator 支持的方式创建与绑定场景/Prefab/材质；用本工程准确 `db://assets/...` 路径，不能凭文件名猜 UUID。
3. 检查现有工作，继续或修复当前阶段，不破坏用户改动。写代码、模块 README 与能验证契约的测试。
4. 保存并重新打开场景/Prefab；在 Creator 预览验证本阶段外观和交互，记录真实环境及结果。
5. 在 `docs/交接记录/阶段NN.md` 逐项记录任务、素材引用、测试、截图、未执行项及风险；标明是否满足进入下一阶段的条件。结束本阶段，不自行接着实施下一阶段。

若 Creator 未连接或工具不可用，可做不依赖编辑器的规则与测试部分；不得手写序列化绕过，也不得把未做 GUI 的任务勾选为完成。若 CLI 未开启，不要求为本任务扩大权限；使用面板内已有工具。
