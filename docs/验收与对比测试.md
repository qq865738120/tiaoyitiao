# 验收与对比测试

本文件是阶段01—04的验证用例参考，验证在对应阶段内完成，不单设验收阶段；当前未执行游戏验收。两个工程独立实施但用相同素材、设计规则、阶段提示词和测试输入。

共同预期数据保存在 [验收基准](数据/验收基准.json)：包含随机数前16项、固定初始平台和之后10个平台参数、蓄力/弹道样点及中心奖励序列。这些是按设计预计算的期望值，不是已通过的测试结果。实际实现应独立运行并对照，不能把基准直接作为生成器返回结果。

## 1. 公平对比前置

- 相同 Creator 3.8.8、Game Agent 0.4.0、机器/浏览器、游戏配置版本、seed=20260930、测试用例。
- 记录实际 Provider/模型、推理设置、命令次序、耗时、工具调用、重试次数；不把 API Key 或会话原文写入共享资料。
- 重置最高分和所有本地运行状态，初始文件哈希使用 `数据/共享基线.json`。参考图与素材不能替换成某个工程新生成的版本。
- 当前工程只能写自己的内容。人工合并修复、复制另一个工程的实现、修改需求或数值后，应说明对比条件已经变化。
- 对比纯规则结果，不要求新增脚本/场景 UUID 或 DOM/渲染帧完全相同。

## 2. 必须覆盖的规则用例

| id | 用例 | 预期 |
| --- | --- | --- |
| R01 | 有效按住/松开、超过 1.2 秒 | 一次跳跃；距离封顶 22，不自动释放 |
| R02 | 不足 0.08 秒、多指、重复 keydown、非拥有者松开 | 不重复起跳；短按取消 |
| R03 | 飞行/落地/移动相机时连续输入 | 不缓存下一跳，不重复计分 |
| R04 | 蓄力期间暂停、失焦、切后台 | 取消蓄力，恢复后重新按下 |
| R05 | 弹道 0、T/2、T | 起点、最高 3.6、终点；T=0.6 |
| R06 | 矩形/圆形安全边界等于、内侧/外侧 0.001 | 等于和内侧成功、外侧失败 |
| R07 | 台面四角、圆台外接正方形角点、阴影范围 | 几何正确，阴影不能落脚 |
| R08 | 中心半径 0.50 与两侧 0.001 | 等于为中心，外侧普通 |
| R09 | 9 次中心、普通命中、再中心 | 奖励 2,4,6,8,10,12,14,16,16；普通 +1 后中心 +2 |
| R10 | 落回当前台、落旧台、目标台 | 当前不计分；旧台失败；目标只计一次 |
| R11 | 同 seed 生成 1000 个平台 | 方向/间隙/scale/模型一致，全部可达 |
| R12 | 重开或回主页时旧回调触发 | 旧 runId 无法加分、结束或播放旧音效 |
| R13 | 存档缺失/损坏/负数/非有限值/写入异常 | 回退 0 或保留有效值，重开仍可用 |
| R14 | 同 seed + 同整数 tick 输入，30/60/120 FPS 渲染 | 平台参数、目标 id、判定、分数一致；落点误差 ≤ 1e-5 |
| R15 | 后台/大卡顿后恢复 | 不用一大段累计时间补算蓄力或跳跃 |

R14 用程序注入 tick 事件。人工按住时长不精确，不能作为确定性证据。至少保留 20 次跳跃含普通、中心、落回当前与失败的回放；输入记录包含 configVersion、seed、tick、source/type。测试应当能故意改错参数后失败，不能仅复制实现公式做无意义断言。

## 3. Creator 与界面验收

开始→游戏→暂停→继续→失败→结算→重开→回主页完整操作。检查三种输入、UI 点击不蓄力、本地最高分重新预览后仍保留；连续重开 20 次后无遗留角色、叠音或重复监听。

| 分辨率/环境 | 关注内容 |
| --- | --- |
| 414 × 736 | 对照三张原图有效内容区，核心元素齐全、排除项完全移除 |
| 375 × 667 | 分数、安全区、按钮、角色和目标不互相遮挡 |
| 390 × 844 | 高屏多余背景正确，结算按钮可见可点 |
| 1280 × 720 | 桌面横屏保留游戏构图，鼠标与空格有效 |
| 30/60/120 FPS 模拟 | 规则一致，动画不因帧率改变时长 |

保存场景再重新打开，确认引用未丢失；在 Creator 预览截图开始、游戏、结算三态，浏览器运行Creator预览即可，不要求Web构建产物。模型外观校正单独记录：纹理方向、透明阴影、默认角色脚底偏移、正交镜头、灯光、材质。不能用离线 Three.js 浏览器截图替代 Cocos 预览。

## 4. 可选的长期观察

有余力时可连续运行200跳或5分钟；这不是额外实施阶段或完成门槛。观察平台池数量有上限（建议 ≤8），监听器/循环音/活跃 Tween 不持续增长。记录机器、浏览器、分辨率、平均/低位帧率及内存趋势；性能目标为当前 Mac 桌面常规预览接近 60 FPS，但没有实测不能宣称达标。

## 5. 结果模板

每个工程自行生成 `docs/验收证据/测试结果.json`，字段包含工程路径/uuid、Creator 与插件版本、配置哈希、seed、执行时间、环境、caseId、expected、actual、pass/fail/not-run、证据相对路径。不要把另一个工程结果当成本工程结果。

对比报告按完成任务比例、一次通过率、规则一致性、视觉质量、耗时、人工干预、遗留问题列出事实；失败与未执行分开。当前交付检查报告只覆盖素材、文档和命令，不替代本文件的游戏测试。
