# Scene/Prefab 验证清单

## 适用场景

适用于所有 Creator 文档、节点、组件、Prefab、UI、2D/3D 和视觉 mutation 的写后验收。

## 决策规则

首次视觉副作用前，先从用户目标、参考媒体和已确认约束中记录可见区分特征、明确失败信号与证据通道；不要把实现计划、节点命名或“产物非空”改写成视觉标准。以下是按目标与影响选择的证据维度，不是每批 mutation 的必跑顺序；复用入口已完成的有效验证，只补缺失或失效的证据：

1. 结构或引用变化时，用 `CreatorInspect` 定点核对受影响节点、组件和 Prefab 关联；不重复查询工具已经完整验证且仍有效的字段事实。
2. 有待保存修改时，`DocumentSave` 使用权威文档身份保存并检查返回的身份/dirty 验证；缺失事实才补查，需要持久化证明时执行 save/reopen。
3. 目标画面缺少有效证据时，`PreviewOpen` 连接当前 Creator Preview 或复用本轮运行，`PreviewObserve` 获取真实画面。先客观记录位置、颜色、形状、清晰度、占比、遮挡、形变和可辨识内容等像素事实，再逐项对照目标特征与失败信号；交互或运行态需求继续用 `PreviewInteract`、`RuntimeInspect`、`RuntimeInteract`、`RuntimeWait`。
4. 相关异常、加载风险或验收要求需要日志时，`DebugInspect` 查询 Preview 日志、网络或性能；Creator 编辑器日志使用 `CreatorInspect(target="console")`，多源归因使用 `DebugDiagnose`。保留输入或修复前的日志游标，增量读取确认新错误，避免把旧错误当成修复失败。
5. 修正后复验失败项和受修改影响的相关项，保留依赖与运行条件未变化的通过证据。共享基础或依赖变化才扩大相关回归；不因阶段切换、任务更新或收尾重跑整链。

只对交付范围内新增或受影响的状态与输入分支执行交互验证；完整游戏交付覆盖实际存在的关键分支。先记录可观察的前态，再发送真实输入，最后核对后态：方向改变、分数/数量变化、暂停后静止及恢复、失败后重开等。`PreviewInteract` 回执只说明浏览器完成输入派发；没有消费输入后的业务或画面证据时，相关验收项继续保持未完成。日志为空也不能替代玩法验证。

实时玩法在模型思考时也会继续推进。需要规划精确操作时，先用游戏正常暂停冻结前态；确认输入有效后，把恢复、移动/旋转/落子、再次暂停放在同一键盘批次，再读取后态。不要为了方便验收改随机规则、减慢正常速度或直接写游戏状态。

制作素材后，先用 `AssetInspect` 确认实际 importer 和 SpriteFrame 等子资产，再按真实导入结构引用。SVG 设计源或普通 Asset 不等于纹理；动态 `resources.load` 必须符合 resources 目录与子资源路径合同。检查资源相关 warning、实际组件引用和最终像素，不能以 error 日志为空宣称加载成功。

## 推荐结构

验收记录按适用范围列出 mutation transaction/Undo、结构复验、保存或重开、Preview viewport、像素事实、目标逐项对照、Runtime 行为、日志时间窗与未执行项。receipt 只证明调用完成，不证明视觉或业务目标完成。空白、占位或默认图标主导、严重拉伸、关键特征缺失、关键内容被遮挡、不可读或观察证据无法判定时必须保持未完成；有意的极简画面若满足预先约定的目标特征且没有失败信号，可以通过，不因元素数量少而自动失败。

## 反模式

- 把字段写入回执当作未观察的整棵树、视觉或玩法证据。
- 因局部修正丢弃所有既有通过证据，或为提交完成状态重跑全部检查。
- 把保存成功等同于 save/reopen 成功。
- 把无 Creator 日志等同于 Preview 无错误。
- 用静态树或组件存在替代真实画面和交互。
- 看到非空画面或能为默认图标“解释”出语义，就反推目标已经实现。
- 先复述实现意图，再让该叙述替代对真实像素的独立观察。
- Preview 不可用时把视觉验收降级为“后续优化”。

## 验证清单

只检查本任务适用项，未涉及的维度不形成额外验收义务；已有有效证据直接引用。

- [ ] 文档身份、目标节点、组件、资源引用与 Prefab 关联已重查。
- [ ] 当前文档已保存；要求持久化时已重开复验。
- [ ] 视觉任务已有 `PreviewObserve` MediaPart 和明确 viewport。
- [ ] 首次视觉副作用前已记录目标相关区分特征、失败信号和证据通道。
- [ ] 验收先记录真实像素事实，再逐项对照目标；空白、占位、默认图标主导、严重拉伸、关键特征缺失、遮挡、不可读或无法判定均未被误报为完成。
- [ ] 运行态任务已有 Runtime 观察/交互/等待证据。
- [ ] Creator 与 Preview 日志来源、过滤条件和时间窗明确。
- [ ] Creator GUI、真机、部署或视觉验收未运行时单独列出。
- [ ] 已有普通原型的复用任务尚未创建第二份普通副本，且 `PrefabCreateFromNode` 的实际源节点身份和关联已复核。
- [ ] 没有把 Prefab 抽取误报为空文档创建，也没有虚构节点转换结果。

## 适用条件

Preview 启动或连接失败且没有等价视觉观察时，视觉目标保持为未完成或阻塞。纯结构审查核对目标结构，不自动要求保存或玩法操作；涉及持久化或行为交付时补充相应证据。
