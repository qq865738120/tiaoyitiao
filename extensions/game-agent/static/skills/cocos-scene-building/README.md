# Cocos 场景搭建技能

`cocos-scene-building` 是 Game Agent 的内置自动技能，专门指导 Cocos Creator 3.7 及以上版本 场景、Prefab、UI、2D/3D 节点树的创建、改造、规划、审查和优化。

## 与 cocos-doc-skill 的边界

- 本技能负责场景结构决策和实施方法论：先盘点当前场景与可复用资产，再规划节点树、Prefab、模板、组件依赖、布局与验证；稳定重复结构优先在 Scene 批量写入前确定 Prefab 路径。
- 当任务由效果图、截图、概念图、样例场景或指定素材集合驱动时，本技能还负责在首次正式写入前建立参考区域、候选素材像素证据、目标结构与视觉验收闭环。
- `cocos-doc-skill` 负责广泛的 Creator API、脚本、编辑器工作流、报错和通用知识检索。
- 场景任务可以按需补充读取 `cocos-doc-skill`，但不得跳过本技能的预检和复用决策。
- 难触发弹框、独立 Prefab 预览及定量效果图核对按需激活 `cocos-ui-preview-testing`；已有效的真实画面可以直接复用，夹具显示通过不代表自然业务触发通过。

## 渐进式披露

```text
SKILL.md
  触发边界、强制流程、工具顺序、复用优先级、静态路由
references/
  按任务主题读取的详细知识
evals/
  触发边界与有无技能对照评测
```

`SKILL.md` 是 Core Agent Tools 3.0.0 的唯一生产入口。含 callable 名称的 preflight、Prefab、参考视觉和验证资料使用独立 `.md`，避免渐进读取时混入退役合同；其余纯领域知识继续共享。

入口包含简单任务需要的完整预检、结构计划和验收流程，不再要求每次读完两份重复通用资料。复杂改造、未知项目资产与深入验收才按需读取 preflight/verification reference；稳定重复结构和已有原型复用在首次大量节点写入前读取 prefab-strategy，参考驱动任务仍先读取 reference-driven-visual-building。简单唯一 UI 不强制多轮资产搜索、Prefab 设计报告或重复组件目录查询。该调整依据真实 Luna 一行 Label 场景用了57次工具调用的轨迹；是否改善效率需同题复验。

包含玩法的场景需在入口保留状态/输入/验收计划与状态转换验证方法，避免只有深入 reference 才提供关键检查。依据全新贪吃蛇首轮实测：初始开始、暂停、普通重开通过不能证明结束弹窗重开通过，模型仍遗漏该分支并报告完成。长任务的验收项由 canonical Task 持有；简单静态标签不需要建立玩法状态或任务台账。

2D 小游戏、Graphics/Label 绘制、屏幕 UI 和 Canvas 场景先使用入口的可见性检查；多渲染根、排序或复合UI再读2D组合页。首次可见场景前核对 UITransform、Canvas/RenderRoot2D、节点 Layer、Camera Visibility、投影与相机位置，并立即看一次真实画面；高级相机/管线问题再按需读取渲染专题。按键验收要比较输入前后的业务状态或画面，Preview 输入回执本身不证明玩法响应。

生成背景与 Graphics 混合时，入口说明普通2D遍历中父渲染组件先于子节点提交，背景应与玩法渲染层成为有序兄弟；setSiblingIndex(0)不能把子背景放到父Graphics之后绘制的内容下面。详细组合页保留条件及来源。此补充依据Creator3.8.8塔防Y的真实画面、独立建塔输入和引擎batcher-2d遍历代码；技能修改的模型效果仍需独立实测。

复用决策按已有项目 Prefab、variant/nested Prefab、第三方/挂载资产、Creator 内置模板、新 Prefab 和一次性节点逐层评估。绿地可先完成新 Prefab 再实例化；已有普通原型在复制第二份前停止，并通过 `PrefabCreateFromNode` 把已核验源节点建立为首个关联实例。必须消费 Creator 返回的新身份并重查关联，不得把 Prefab 抽取误报为空文档创建。

`AssetSearch` 返回的名称、UUID、类型和路径只证明资产身份或候选关系，不证明模型已经看过像素。参考相关候选必须逐一完成视觉读取或明确排除，且 Preview 无法启动或连接时，视觉任务必须保持未完成或明确阻塞。首次视觉副作用前记录目标相关区分特征、失败信号和证据通道；验收先写真实像素事实再对照目标，不能把默认图标、占位内容、非空画面或实现意图当作完成证据。

## 证据规则

验证维度按交付范围、实际改动及依赖选择；结构、持久化、画面、运行和日志不是每批修改的固定流水线。入口与深入清单均保留未受修正影响的通过证据；局部视觉改动不自动触发全部玩法回归，共享输入/状态改动仍覆盖受影响分支。阶段与最终完成可使用同一份有效证据，视觉或业务结论仍须真实观察。

实时游戏使用正常暂停与同批输入避免思考期间状态继续推进。导入图片需核对实际 importer/sub-assets、加载路径与画面；源 SVG 或普通 Asset 不能直接充当 SpriteFrame。资源加载警告也属于验收证据，不能只查询 error 后宣布素材加载成功。

核心结论按以下优先级取证：

1. Creator 3.8 官方文档。
2. Creator 3.8.4 引擎源码和公开类型声明。
3. Creator 3.8.4 内置 Prefab 模板。
4. 可复现的 Creator 实机行为。
5. 社区资料只作为线索，不直接写成核心规则。

在 3.7 项目中，3.8 文档和源码仅作为候选知识，须先核对实际宿主的组件描述、模板、资产和 Preview。非全部支持版本通用的能力必须标注适用条件。模板中的精确节点、组件和引用应标注实测版本，并在目标项目中重新检查。

## 维护与验证

- 通用格式、description 边界、相对资源、脚本/eval 与发布包含遵循随扩展发布的 `static/skills/AUTHORING.md`，先运行 `npm run skills:validate`。
- `npm run cocos-scene-building:validate`：验证 frontmatter、静态路由、十三个知识页、来源、参考证据门禁、结构所有权、视觉闭环、评测集和本机路径泄漏。
- `npm run cocos-doc-skill:validate:full`：修改旧知识卡后验证其路由、链接和内容质量。
- Creator 实机、真实模型对照和冷安装不属于纯 Markdown 校验；未执行时必须在交付报告中单列。
