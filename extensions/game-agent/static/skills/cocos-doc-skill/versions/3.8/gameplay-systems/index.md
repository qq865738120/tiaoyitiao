# Gameplay Systems

本目录存放可复用的游戏系统设计：职责、状态、接口、组合与扩展点。

## 分类说明

### 是什么

- 可复用的游戏功能模块设计（背包、对话、技能、Buff、任务、存档等）
- 系统的**职责边界**：该系统负责什么，不负责什么
- 系统对外暴露的**接口/API**（方法签名、事件、回调）
- 系统的**内部状态模型**与生命周期
- 系统与其它模块的**组合方式**与**扩展点**
- 数据驱动的配置结构（JSON/资源表的设计原则）

### 不是什么

- 某个具体游戏项目的专用业务逻辑（硬编码的英雄名字、关卡数据）
- 仅描述 Cocos 内置 API 的行为而不涉及系统级封装
- 逐步教程（属于 `recipes/`）
- 纯粹的性能优化技巧（属于 `troubleshooting/` 或架构文档）

## 进入条件

创建 gameplay-systems 文档前，确认：

- 描述的是一个**可跨项目复用的游戏系统**概念
- 明确说明了**职责边界**（该做什么、不该做什么）
- 有清晰的**对外接口定义**（方法、事件、配置入口）
- 说明了**内部状态模型**（什么状态、如何变更）
- 提供了**组合方式**（如何挂载、依赖关系）与**扩展点**（如何自定义）

## 排除条件

以下内容不适合放入 gameplay-systems/：

- 仅绑定到特定项目的硬编码业务逻辑
- 单一 API 或组件的使用说明（如 "Button 的 clickEvents 怎么用"）
- 核心是架构模式选择而非系统设计（属于 `architecture/`）
- 纯 UI 布局说明（属于 `ui-2d/`）

## 章节模板

新 gameplay-systems 文档应包含以下章节：

1. **概述**：系统解决什么问题，核心职责
2. **职责边界**：该系统做什么、不做什么（正反例）
3. **内部状态模型**：状态定义、状态转换图/说明
4. **对外接口**：公共方法、事件、回调签名
5. **配置结构与数据驱动**：JSON/表格配置的字段含义与设计原则
6. **组合与依赖**：依赖哪些模块，如何挂载到场景/节点
7. **扩展点**：开发者如何自定义行为（继承、钩子、策略模式等）
8. **完整使用示例**：从初始化到典型调用的最小可运行示例
9. **常见误区与边界处理**：高频使用错误与边界条件处理
