# UI 生图到 Prefab V2

## 2.8.0 成品可用性优先

新运行按 `prefab-usability-v1` 判断发布。公共抠图仅因前景颜色估计不确定时，若背景证据可靠、候选主体完整且保留透明空白，UI 提取器可消费候选并记录 `UI_MATTING_CANDIDATE_USED`；公共 `review_required` 与原图/报告保持原样。源层重新排版使用已确认的源框到左上目标框映射，像素模板校准为可选增强。已具备有效切片及目标框的图层错位、额外文案只作告警。未消费的右下图层维持辅助地位，普通文字继续原生 Label。缺失素材、必需语义、非法结构和 IO 故障仍阻止发布。下文历史版本的更严格图层门槛描述不覆盖本节新运行策略；实际成品允许少量色边、字体和装饰差异，仍需 Creator 视觉验收。

2.8.1 对左上可见但左下明确缺源的非交互 Sprite，允许从左上效果区域直接取材，排除需要独立编译的 Button/Label 区域，并保存 `effectSources` 及 `UI_EFFECT_SOURCE_RECOVERED`。这类素材可带背景，不承诺独立透明角色；背景接缝是可接受的待修饰项。未知源、不可见元素、交互节点和明确文字不使用此兜底。

2.8.2 连通区域的语义归属使用双向覆盖：一个角色包含多个分离部件、一个小按钮位于较大的接触区域内，都可映射到完整物理组；后者须有该区域真实前景像素支持，空洞内的框不会获得归属。物理组保留整块画面，Button/Label 保留独立目标框。低相似度像素匹配不再覆盖已确认的语义目标布局。

该内置工作流用一张四象限复合图统一视觉基准，再将可编辑语义确定性编译为 Cocos Creator 3.8 Prefab。V2 完全替换旧候选图、OCR/ONNX、独立载体生成和自定义质量分路线，不保留双实现。

## 节点链路

1. `parameters`：沿用原有用户参数，画布默认值改为 `1920×1080`；新增可选 `referenceUiImage`。参考图可来自 Creator 项目或本地文件，只以 run-scoped Artifact 传递，Renderer、检查点和日志均不持有路径或 Base64。
2. `intent` / `intent-normalize`：语言模型理解需求和可选参考图；脚本以用户 `requiredElements`、`exactTexts` 为语义权威，补齐遗漏并生成四象限提示词。
3. `generate`：调用现有图片 Agent 生成一张复合图。运行时优先选择模型能支持的最高分辨率：精确尺寸模型优先使用两倍目标画布，其他模型选择最高 resolution 且最接近目标宽高比的合法 profile。模型不支持参考图时，保留已识别意图并带警告继续。
4. `observe` / `observation-normalize`：语言模型按左上效果图解析目标画布坐标、层级、锚点、贴边约束与 Label 样式；脚本用 Intent 复写普通文字语义，钳制几何并把缺失、非法父节点或环转为 `review_only` 证据。
5. `extract`：Python 3.11–3.13 + Pillow/NumPy 容错检测中心深色分隔带，切出效果图、背景、UI 元素和普通文字四区；下方两区以原 composite handle + 存储像素 region 调用公共 processImage：可信原生 Alpha 原样派生 PNG，纯洋红备用背景执行连续 Alpha 与边缘去混色；被实际裁片消费的图层质量不足进入 review_only，普通 Label 独立重建。UI 元素按原生 Alpha 连通主体分组提取，保留主体边缘与安全区，并保存语义成员映射。
6. `blueprint`：生成 V2 蓝图。右上象限作为唯一权威背景 `cc.Sprite`；只有节点自身明确属于右上静态背景时才抑制重复 Sprite，不按祖先容器名称删除动态图像。`requiredElements` 只承担验收语义；若 Observation 将它再次展开为覆盖整组 HUD、菜单或导航的 ROI，则保留其布局容器、移除重复 Sprite/Button 裁片，实际视觉与交互由已拆分的子节点负责。动态/交互图片使用独立或有成员映射的 group `cc.Sprite`，普通文字使用 `cc.Label`，按钮额外生成无事件的基础 `cc.Button` 状态，贴边节点生成完整 `cc.Widget`。最终 Review 同时引用原始复合图、四象限、分隔线 overlay、切图、Observation、Blueprint 和发布事实，并保留实际生图规格与参考图能力模式。
7. `publication-gate` / `publish`：`ready` 和 `ready_with_warnings` 可进入唯一发布步骤；结构不安全时返回 `review_only` 和 Review/Manifest/Blueprint，不产生项目副作用。发布脚本先提升图片素材，再用 `creator-3.8-prefab-json-v2` 编译对象表，最后通过 AssetDB 发布并复验 `.prefab`。

## 四象限合同

- 左上：完整效果图，是几何和最终视觉核对标准。
- 右上：纯背景，只含无需动态处理的背景与装饰；不得包含文字、按钮、图标或交互元素。
- 左下：透明底 UI 元素层，位置与左上严格一致；只含动态图标、按钮、交互元素和艺术字，不含普通文字。
- 右下：透明底普通文字层，位置与左上严格一致；不得包含 UI 元素或艺术字。
- 右下按左上普通文字的原位透明覆盖层生成：仅移除非文字像素，逐字保留位置、字号、颜色、描边、换行、对齐与空白；平移回左上后应完全重合。语义节点和文字核对数据只用于理解内容，不把字段名、数据分隔符或清单排版画入图片。左下须移除所有普通文字，包括顶部资源数值和底部小按钮文字，保留对应底板、图标与艺术字。
- 中心使用约 2 px 深色水平/垂直分隔线。切割器先确认贯通的深色核心，再在有界邻域内检查逐像素向外变亮并连续稳定的过渡，包含偏色抗锯齿边缘后再提交象限给公共抠图；证据不足时保留原核心边界，不固定裁边。没有可靠核心候选时回退到几何中心并记录警告。
- 提示词区分目标单象限与整图：期望整图宽高为目标画布的两倍，2×2 等分且局部坐标一致，UI/文字不得重新排版为素材表；实际输出规格由最高兼容 profile 决定。请求显式为 `background=transparent`，交给现有 Provider 的 native/adaptive/local 策略处理；左上/右上保留完整不透明背景，只要求下方层的空白为真实 Alpha，禁止棋盘格、白底和透明示意图。无法输出真实 Alpha 时，同一次生成将下方空白填为纯洋红 #FF00FF（非渐变、棋盘格）；后续公共接口抠图，不自动二次生图。用户要求洋红主体或存在未核验参考图时禁用键色备用并保留真实 Alpha 要求。

## 权威与降级

- `intent-v2` 的完整脚本输出（含 `imageRequest` 与 `intentArtifact`）必须通过 `workflow.json` 声明的输出 Schema；`imageRequest.background` 固定为 `transparent`，脚本与声明必须同步更新。已有运行保留冻结定义，修正 Schema 后应新建运行，旧检查点不能直接跨定义恢复。
- 用户输入决定必须元素和精确普通文字；左上效果图决定布局坐标；语言模型只能解释视觉几何，不能改写用户语义。
- 普通文字必须保持 `cc.Label` 可编辑；只有明确的艺术字才作为图片切片。
- `ready_with_warnings` 允许完成流程并显示结果；`review_only` 保留全部可审查产物但禁止发布；真正的输入损坏、运行时缺失或授权失效才作为 fatal 终止。
- 真实验收版本固定为 Creator 3.8.0 与 3.8.8，并且必须通过 Cocos Dashboard 打开；Provider、Creator 导入、保存/关闭/重开和视觉验收分别记录，不能互相替代。

## 运行时依赖

图片处理脚本只使用 `requirements.lock` 中带 Hash、仅二进制 wheel 的 `Pillow==12.0.0` 与 `numpy==2.4.1`。Workflow runtime 在隔离 Python 环境中安装依赖；不提供 Node.js 图像处理回退，也不随包携带 `node_modules`、OCR/LPIPS 模型或字体资源。

## 包闭包

生产定义只引用 `brief-v2.cjs`、`intent-v2.cjs`、`observation-v2.cjs`、`extract.py`、`quality-v2.cjs`、`blueprint-v2.cjs`、`publish.cjs`、`lib/runtime.cjs`、`lib/audit-contract.cjs` 与 `lib/prefab-compiler.cjs`。任何新增脚本、依赖或资源都必须先进入 `workflow.json` 的声明闭包，并继续满足 Creator 3.8.0 的 Node.js 14.16.0 / Electron 13.1.4 宿主基线。

## 公共处理与版本

2.1.0 引入共享处理闭包；旧 run 不跨摘要静默采用新算法。原始下方象限、处理后 PNG、公共报告和重建预览均保留在 Review。没有相应语义元素才允许空层，源图必须证明为空；处理后擦空不能作为证据。上方两区不进入抠图。纯色同色前景无法从单图唯一恢复，键色独占是调用约束，不能由算法冒充证明。

## 2.2.0 观察草稿合同

observe 只在 box 容忍附加字段，正式坐标仍必填；observation-normalize 使用同一输入 Schema，逐项构造封闭正式 box，并以节点索引/数量记录忽略警告。脚本确定性生成唯一 ui-root；Intent 的顶层内容容器保留语义 ID 并挂到它下面。显式合法结构根被规范化并记录警告；parentId=null 的顶层内容节点确定性挂到 ui-root，不因安全的根归并阻断发布，保留 ID 冲突、错误 parent、重复 ID 和环继续阻止发布。旧冻结运行不跨定义版本恢复。

## 2.3.0 语义与切图完整性修复

### 真实 Creator 3.8.8 质量修正

- 原生 Alpha 只有轻微端点噪声、并在至少三个子区域存在分布式近透明空白时，可对 16 以下 / 240 以上端点做有界线性降噪，再由同一公共处理接口验证派生图。少量精确透明像素（不足 1%）不会掩盖其余像素的噪声；主体本身已有全不透明像素也不影响这一判断。原图和首次报告保留；均匀半透明、缺少分布式空白或正常透明图不会进入此分支，不把颜色背景猜测为透明。恢复以 `UI_NATIVE_ALPHA_NOISE_RECOVERED` 明示。

- 蓝图位置使用节点及父节点的实际锚点计算，保持左上像素框不变；Widget 仍以边距定义布局。
- 实际文字层按 Alpha 行与词间空隙建立候选框。至少三行的文字行数和每行数量一致时，优先按从上到下、从左到右的一一对应，避免最近距离贪心匹配串行；排除不足一个普通字形的孤立噪点。按钮文字始终保留其在原按钮内的相对位置，随对应物理按钮区域一起映射，不允许字形匹配把标题移到旁边背景中。非按钮文字只有在行结构对应成立，或至少 6 个 UI 节点呈现整批缩略图比例混用时才进行字形对应。只修正 Label 几何，文字内容仍来自 Intent，不进行 OCR 改写；无可靠对应保留原框并报告。
- 普通文字的实际图层偏差只记录警告，仍按已确认文本和目标框生成 Label，不以源图层归类阻断导入。残留在象限边缘的贯通深色分割线先从分组分析中去除，避免边线与装饰相连后形成覆盖整张 UI 的伪分组。每个裁片只保留自身连通像素及透明边缘，不带入其包围矩形内的其他独立图标。
- 生图仍要求艺术字进入左下区。实际图片将艺术字放在右下区时，允许按 Observation 的真实 `sourceLayer=text` 提取艺术字并告警，普通文字继续生成可编辑 Label。
- 模型框是语义定位范围。Python 先根据可见 Alpha 连通主体修正小幅漏框，保留原 Alpha 边缘和 1 px 安全区；合并的主体不无界扩张。尚未可靠拆开的接触区域和未映射前景保留具体告警与 Review，继续输出可查看的 Prefab，不能把这些告警称为视觉验收通过。
- Intent 必须将按钮文字、昵称和资源数值显式拆为 Label；生图提示词区分 UI 图片语义与普通文字核对数据，核对数据不提供独立排版指令。
- 对切片在左上效果图附近进行有界 Alpha 模板匹配，修正源层偏移和模型估计框引入的非等比拉伸；匹配证据不足时保留观察坐标，匹配事实随切片保存。这是坐标修正，不是终止流程的质量分门禁。
- 原生 Alpha 中已连接为同一位图的标题/角色/底板，按完整连通主体输出 group Sprite 和 `groupMembers`。语义节点与 Button/Label 保留；group 挂到语义成员的最近公共祖先，随按钮或布局容器移动，已经包含在 group 中的图标不重复绘制。未被模型命名的实际可见主体也作为有据可查的图片节点保留，不能切断、遗漏或虚构其名称语义。

- 工作流不设置生图 Prompt 字符上限，不截断或删除语义清单；完整传递名称、角色、建议/精确文字与参考观察。Provider 自身能力校验仍保留。未填写 exactTexts 时保留模型建议文字；模型仍未给出内容的可选 Label 会被告警并移除，不发布空 Label。
- Observation 显式声明 visualStatus、sourceLayer 与 sourceBox：box 始终表示左上目标布局，sourceBox 表示对应源象限的局部坐标（同样换算为目标画布像素）。无法定位时为 unresolved，禁止 1×1 框冒充可发布内容。用户 requiredElements/exactTexts 缺失时保持 review_only；模型展开但图中不存在的建议节点只记录 warning 并移除，不再制造占位节点。有明确视觉证据的额外非文字 UI 可保留，记录 warning；右上背景的额外 sprite 描述同样可保留，并由唯一背景 Sprite 承载，不重复绘制。纯布局 container 的源层统一为 none、源框为 null，模型误填图层只警告；实际可见像素仍由物理分组保留。
- 提取按 sourceBox 裁切并映射回 box；源框的小幅边缘溢出取与画布的交集并记录 warning（每轴不超过画布的 5% 且至少保留源框的 80%），不改写左上目标框。完全越界、损坏及占位坐标仍不可发布。原位偏差、截断主体、重复源区域及显著未映射前景保留诊断警告；完整物理分组尽量恢复这些区域，不以节点数量或文件存在替代完整性。
- 背景归属由节点自身 sourceLayer 决定，普通内容容器可以合法包含动态 Sprite。旧运行保持原冻结定义，修复后新建运行；不自动重新生图。

## 2.4.0 有界纠错

intent/observe 使用无工具模式，结构化及 observe 语义纠错共享每节点最多 2 次额度。语义只重跑 observe → observation-normalize，复用原 Intent 和四象限图片；重复 ID、根、父关系、环、目标框非法且没有其它阻断原因时可纠错。视觉、源层与缺像素问题继续 review_only，不自动重新生图；额度耗尽保留最新合法诊断结果。

普通文字覆盖层修正只更新生图提示词，不改变数据 Schema、提取、发布或重试策略。离线回归覆盖横屏、竖屏、方形、有无参考图、建议/精确文字及艺术字分层；真实生图另核对顶部、中部、底部文字与左上的位置和样式是否重合，以及左下普通文字是否全部清除。测试通过不代表像素对齐验收通过；旧图不随提示词修改而改变，应新建运行验证。

## 2.5.0 图片校验纠偏

新运行启用 policy v2：quality-validate 聚合当前图的 Alpha 与结构化图层审计；不合格时最多三次额外图片请求，每轮基于原始 Prompt 追加累计去重纠偏，并重新 observe/normalize/extract。通过后才构建蓝图与发布，耗尽保留 review_only。真实 Alpha 或经过公共处理的合法纯色背景均可通过。普通 Label 的左上可见性独立于右下字形来源，源层缺字不能删除可靠 Label。Alpha 失败不输出伪整层物理组。此前不自动生图的约束继续适用于旧冻结运行和单纯观察结构纠错。

## 2.5.1 审计不完整时的恢复

已通过区域、语义和图层验证的图片问题可独立触发生图纠偏，整体 `layerAudit.status=uncertain` 不否决这些证据；不确定标记仍保留，不能据此通过发布。非法审计项、未识别的处理故障及结构/IO 错误继续阻止图片重试。

只有 `uncertain` 且没有审计问题时，observation-normalize 返回 `audit-incomplete`，复用原图进入现有 observe 纠错组，共享每节点最多两次纠错、全局额度与期限；不得添加图片请求或重置额度。补充观察后仍无可靠结论时保留 review_only；后续像素报告确认 Alpha 问题时仍可按其独立证据纠偏。新图必须重新完整校验，旧 Session 不回填、不自动恢复。

## 2.5.2 观察语义合同校验

观察与图片质量校验共用图层审计合同：effectVisibleLabels 只能包含 Intent 中普通 Label 的 semanticKey，required-missing 只接受用户 requiredElements/exactTexts 的权威必需项，审计区域、角色和图层必须一致。语义非法的审计和已有合法源框但选择了错误源层的普通图片节点，先复用原图进入既有观察纠错组（schema-invalid），共享原两次纠错及全局额度。不得把非法审计作为付费生图依据；真实缺源、未知像素和本地 IO 故障保持拒绝。新版本仅用于新运行。

观察阶段额外提出的 unresolved 建议节点与 Intent 中可选建议采用同一告警降级，不升级为用户必需项；已映射的整组像素继续保留。声称 visible 但没有合法源层证据的新增节点仍拒绝，所有用户必需语义仍按原门禁验证。

## 2.5.3 纯文字象限约束

首图及内置纠偏统一要求右下从空白透明画布开始，仅复制左上普通文字字形及字形自身描边、阴影；不得复制承载文字的控件。按钮、资源条、徽章、图标、装饰、艺术字及其整块底板全部移除，原文字位置、尺寸、换行和四周留白保持不变。移除底板不能触发文字重新居中；空白使用既有真实 Alpha/合法键色合同。真实图像仍由原审计验证，提示词测试不能替代纯文字像素验收。

## 2.5.4 内容归属与合成关系

针对真实 R04 多轮纠偏仍复制艺术字及导航小字，提示词改用三类内容的明确归属表：背景仅左上/右上，UI 与艺术字仅左上/左下，普通文字仅左上/右下；左上为三层合成。位置一致仅指每层保留内容的原位关系，不要求复制完整控件。左下要求完整无字底板，既不烘焙小字，也不挖字形孔洞。所有语义数据、四象限、原位纯文字和质量门禁保持。该提示词设计仍须真实生图验证。

## 2.5.5 观察文字角色权威

观察提示词与已有校验合同一致：已声明的文字角色冻结在 Intent，实际字形增加描边、阴影或立体外观不能把普通 Label 改成 artistic-text。art-in-text 只描述 Intent 已确认艺术字的源层污染，普通文字外观偏差保留在 evidence；effectVisibleLabels 依旧按 Intent 普通文字语义记录。移除原提示词按实际外观重新分类的冲突指令，避免同图纠错反复产生相同非法审计并阻断已确认的 Alpha 纠偏。此修正不改变质量门禁、问题代码或图片策略。

## 2.6.0 当前图编辑纠偏

新运行以当前待纠正复合图为第一参考，冻结用户参考随后保留，通过现有编辑接口纠偏；不累计失败图片，不静默丢弃必需编辑参考，仍最多三次额外图片请求，每轮完整复验。unplanned-text 只以空 semanticKey、有界区域记录 Intent 外普通文字，不创建新 Label；source-missing 只接受左上可见且目标框有效、对应 UI 源确实缺失的 Intent 图片元素，未知缺源仍拒绝。visualStatus 描述左上可见性，源像素可用性由 sourceLayer/sourceBox 独立表示。

真实 R07 Preview 发现系统字体宽于生成字形时，固定框 CLAMP 会截断精确文字。普通 Label 在保持原几何、位置和完整文本的前提下使用 Creator 的 SHRINK 自适应字号；不扩大框、不移动文字，不修改用户文本。实际字体与图片仍可能不同，需在 Creator Preview 核对。

## 2.6.1 新增观察节点的源证据准入

Intent 外新增 Sprite/Button 必须同时具备真实源层与合法 sourceBox；只有效果图可见、源像素未确认的草稿不进入正式图片节点，返回既有未声明节点合同错误并消耗同图纠错额度。不能把缺乏准入证据的模型建议提升成正式节点后再当作不可恢复的实际源丢失。Intent 图片的未知缺源仍拒绝，不变成付费生图依据。

## 2.6.2 基本可用与视觉瑕疵分级

用户允许少量瑕疵产出。已通过语义、结构、源像素和提取检查时，单独的整体审计 uncertain 只保留警告，不再强制重新观察或阻断发布；具体非法证据与已确认问题仍按原规则处理。纯文字象限不得包含 UI，文字位置不变，必需内容、真实 Alpha、有效切图及可导入结构仍是硬要求。

仅可选非交互 Sprite 的轻微 UI 层偏移可降为警告：最多两项，累计目标区域不超过画布 10%，每轴偏移不超过画布短边 1% 且不超过该节点短边 5%，宽高差各不超过 5%。必须有可信、画布内源框和目标框，差异有数值证据。Label、艺术字、Button、必需节点、大范围偏移、未知源不适用。允许的瑕疵写入 manifest.warnings 并输出 ready_with_warnings，原审计完整保留在 Observation；不得删除原图或把警告当成无瑕疵验收。

## 2.6.3 功能、风格与观察职责

借鉴用户提供的 [prototype-interaction-game-ui Skill](https://github.com/guiguiyan930-source/prototype-interaction-game-ui/blob/main/SKILL.md) 的功能优先、风格分离和可拆分设计方法，结合本工作流现有合同重写提示词。Intent 先辨认页面任务、信息主次和控件关系，输出最小充分语义；不把通用页面示例自动补成资源栏或额外文案。生图先组织功能，再确定统一色彩、形状、材质、字体和背景层级，四象限与纯文字原位合同不变。观察按坐标标定、语义覆盖、功能父子、源证据和独立审计的顺序解析；只描述当前可见状态，不臆造状态、交互事件或隐形节点。按钮 Label 是子节点，坐标仍统一为目标画布全局框，由编译器换算父坐标。保持现有 JSON Schema，不输出 Skill 的 Markdown 表格，也不引入额外 Provider 调用。

真实 R10 连续三张图把透明空白画成不透明棋盘格。2.6.3 在既有 keyColorIsBackground 安全判定为真时，首图明确选用纯洋红编码空白；共享抠图仍做全部像素质量验证。用户要求洋红或存在未经核验参考图时保留真实 Alpha 路线。这里只消除生图要求中的两种空白表示歧义，不放宽公共处理门禁、不猜测抠棋盘格，也不增加请求。

## 2.6.4 已恢复布局参与质量判定

R11 首图提取已通过，普通文字通过局部字形匹配恢复到左上目标位置，按钮文字依附对应按钮，星星通过 Alpha 模板匹配回到效果图；旧质量门禁仍因原始图层偏移触发编辑，后续图片明显退化。质量阶段现在区分原始图层问题与提取已恢复的问题。仅当无提取错误、源框/目标框有效、恢复位置接近已确认左上框，且有强像素证据时，将 layer-misaligned 记为 UI_IMAGE_QUALITY_ALIGNMENT_RECOVERED 警告。普通文本要求字形相关度至少 0.8；按钮文字要求唯一对应的可靠按钮裁片与按钮相对文字恢复；图片要求唯一语义裁片、local-alpha-template 且截断颜色误差不超过 20。恢复框每轴中心误差不超过画布该轴 2% 与目标尺寸 10% 的较大值，尺寸为目标的 0.8–1.25 倍。错误、缺源、污染、模糊证据或大幅漂移不适用。

生图仍要求纯文字原位，原始图层偏移保留在 Observation/Review，不宣称原图像素完全对齐。发布几何使用已有提取器恢复的左上目标框，不修改源图、不回退旧图片、不调整已结束运行。新运行用同一证据链验证基本可用。

R11 编辑后文字确实消失时，草稿用 unresolved 和零框表示不可定位。只有 visible 节点要求有效可发布目标框；unresolved 节点继续带 VISUAL_UNRESOLVED 阻止发布，不再附加虚假的 BOX_INVALID 掩盖已确认 required-missing。仅完整匹配用户必需项的已验证缺失审计可进入既有图片纠偏；未知缺失仍拒绝，不发布占位节点。

## 2.6.6 按实际内容生成字体与分层约束

R12/R13 原图将普通标题画成立体字并重复到左下。生图说明按冻结 Intent 的 artistic-text 白名单构造 UI 层定义；白名单为空时明确本页没有艺术字，标题也属于普通文字，左下禁止任何字形。普通文字的平面字体约束放在统一视觉语言中，避免材质指令泛化到所有字形。真实艺术字仍按用户语义进入左下，右下普通文字及原位合同不变；不把视觉风格反向改为文字角色。

## 2.7.0 按实际消费重建并隔离分层瑕疵

依据用户关于冗余兜底的补充要求，落实既有普通文字独立编译和安全隔离合同。右下仅为可选几何/样式证据，普通文字以冻结内容和已确认左上目标框生成原生 Label。没有实际图片裁片消费右下时，其缺字、错位、UI 污染及透明处理失败保留为警告，不阻断左下提取。真实从右下提取艺术字时仍必须验证所消费的像素，不把原始脏层整张用于 Prefab。

左下已审计为普通文字的独立连通块，只有对应可重建 Label、完整落在审计区域内、且不接触任何图片节点源区域时，才从派生 UI 层中排除。原图及处理报告保留，记录排除区域、像素数和语义身份；不得擦除与按钮或插画粘连的字形。发布检查消费这些确定性恢复事实，保留原始分层违约为告警，未恢复的缺源或结构错误继续阻断。

UI 与左上效果图模板匹配排除已确认原生 Label 的覆盖区域，因为正确的无字底板本就没有这些文字。每个候选仍须至少 12 个且占原样本 55% 的非文字样本；少于此支持量不产生像素匹配结论，报告保留总样本数、实际样本数及文字遮挡排除事实。颜色误差门槛不变。

## 2.7.1 辅助文字层与组合裁片的独立证据

右下继续以纯文字原位覆盖为生成目标，但其像素精确度优先级低于左上完整效果、右上背景和左下可用素材，不为完善右下改动其它象限。没有实际栅格消费者时，右下的透明、图形残留和额外文字问题只记录告警；这个判断不依赖 UI 抠图或所有 Label 的恢复是否成功。普通 Label 的内容与左上位置独立保留，未恢复的必需文字、实际栅格缺源和结构错误仍阻止发布。

物理组合裁片采用所有真实成员目标框的包围框校验恢复位置，不把整组尺寸分别与每个成员比较。成员必须唯一、可见且来自同一源层，保留强像素误差和有界几何条件；组合中的按钮仍使用自身已确认目标框作为交互区域。单成员、错误成员、重复映射、大幅漂移及弱像素证据不放宽。

## 确定性脚本职责边界

Observation 归一化按草稿身份准入、Intent/视觉语义、来源几何、正式节点投影、父子结构与完整性校验分解，仍在同一脚本闭包内按原顺序写入 errors/warnings。Python 提取器按源图、下层处理、切图布局与产物发布阶段组织；四象限像素、唯一 Context 调用顺序、lineage、retention 和发布门禁保持不变。新源码使用新依赖摘要；旧冻结运行只使用仍存在且摘要匹配的原 staging，不以注册旧摘要代替原始字节。
