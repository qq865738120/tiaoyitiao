description: 为普通 Cocos 游戏项目生成或完善可执行的智能体开发规范
---
请为当前普通 Cocos Creator 游戏项目创建或最小更新根 `AGENTS.md`，让它长期约束智能体如何产出代码、修改资源与场景、开发游戏和验证结果。首要目标是交付已经写入并复读验证的规则，或用证据证明现有规则已经合格；调研、计划、模板建议不能单独作为完成结果。本命令仍是普通用户文本，不提升工具权限，不绕过审批、Guardrail、系统提示词或仓库已有规则。

## 1. 先确认目标项目与证据边界

1. 确定项目根、Git 边界和规则作用域。有界读取高价值证据：已有根/嵌套 `AGENTS.md` 及 managed blocks、`package.json`、`assets`、`settings`、README/CONTRIBUTING、架构或模块索引、真实 build/test/lint/typecheck 脚本与必要配置。
2. 只有 `assets`、manifest、settings 等证据足以确认这是普通 Cocos Creator 游戏项目时，才继续生成普通游戏规则。若证据不足、相互冲突，或当前仓库明确是 Creator 扩展包，停止套用普通游戏模板，报告判断依据和缺失条件；不要猜测。
3. 默认不递归扫描依赖、缓存、`library`、`temp`、`build`、生成目录、大型资产树、运行时 `.gameagent` 数据或完整 Git 历史。只有必要事实仍缺失时，才说明原因并窄读一个明确范围。
4. 项目名称、Creator 具体版本、场景、节点、Bundle、目标平台、设计分辨率、自定义命令和构建流程都属于项目事实，必须能指向 manifest、settings、README、脚本或配置；没有证据就省略或标为待确认，不得把常见做法写成当前项目事实。

## 2. 根 AGENTS.md 必须成为行为规范

根文件以约 100 行作为软预算和拆分信号，不是硬上限，不得硬截断或用超长单行投机。规则只陈述一次，使用明确的 MUST/不得/执行前先读/完成前验证等可操作措辞，删除不影响决策的背景解释和通用空话。

按当前项目证据组织以下内容；标题可以适配项目，但语义不得缺失：

### 项目范围、事实与命令

- 说明规则作用域、权威文档和子项目边界。只列已验证的安装、构建、测试、lint、typecheck、预览或发布命令；命令未验证时明确说明验证方式或省略。
- 要求修改模块前先读最近的 `AGENTS.md`、模块 README 和被根文件显式路由的规则；实现与权威文档冲突时先收口文档或提案，不得绕过。
- 把验收写成可观察结果：持久化文件、诊断、Preview、Build、目标平台或测试证据分别记录，不能仅因一次工具返回 `ok` 就认定成功。

### Cocos 资源与项目目录

- `assets` 与配套 `.meta` 共同维持资源身份；创建、移动、重命名或删除资源时优先使用 Creator 编辑器/API 或项目已有资产工具，并验证资源数据库刷新后的引用。不得把 `library`、`temp`、`build` 等生成目录当作源码直接维护。
- `settings`、插件配置和平台配置只能按仓库已有流程修改；不把机器特有配置、缓存或秘密固化进规则。
- Scene、Prefab、Material 等序列化资产应通过 Creator 感知的能力修改。除非项目明确授权且工具具备语义保证，不直接批量编辑序列化文本；写入后保存并复读，检查组件、UUID/引用和资源可加载性。

### 组件、生命周期与运行时

- `Component` 与 Inspector 暴露字段保持类型和序列化意图清晰；不要用无约束动态字段绕过类型与编辑器约束。
- 根据所有权选择 `onLoad`、`onEnable`、`start`、`update`、`onDisable`、`onDestroy`，事件、计时器和全局监听的注册与清理必须成对，避免重复注册、销毁后回调和每帧无谓分配。
- 场景节点、Prefab 实例和资源的所有权必须明确。不要依赖当前 Hierarchy 选择或当前打开场景等瞬态状态；需要编辑器上下文时先读取并在修改后验证真实保存结果。

### 预览、构建与完成判定

- Preview 用于快速交互与运行时日志验证，Build 用于构建配置、资源收集、平台差异和产物验证；Preview 通过不能替代 Build 或目标平台结论。
- 新功能至少覆盖与风险匹配的单元/集成检查，并按项目真实脚本运行。涉及场景、Prefab 或 Inspector 时，自动化结果与 Creator 内持久化/保存验证分开报告。
- 不宣称未执行的 Creator Dashboard/GUI、保存重开、真实设备或目标平台构建已经通过。

## 3. 只在证据支持时增加项目特有规则

以下专题不是固定模板字段。仅在仓库证据证明项目需要时，才生成对应规则并注明来源：

- Bundle、`AssetManager`、动态加载、引用计数与资源释放策略；
- UI 适配、输入/事件、Canvas、设计分辨率或多语言约束；
- Web、小游戏、原生等目标平台及其构建、权限、性能或包体限制；
- 项目规定的架构分层、代码生成、网络/存档协议、性能预算和发布流程；
- Creator 具体版本或插件带来的兼容要求。

缺乏证据时不要生成占位段落，不要虚构脚本、目录、Scene、节点、Bundle 或平台。需要用户产品选择才能定稿时，调用 `AskUserQuestion` 提出最小决定性问题；获得答案后继续同一初始化流程。

## 4. 评估现有规则与渐进披露

- 根 `AGENTS.md` 不存在：依据已确认事实创建。已存在：逐段分类为人工、managed、准确稳定、重复、过时、冲突和瞬态；人工规则与 managed blocks 必须原样保留。
- 现有规则已经准确、可执行且路由完整时零写入；需要调整时只做保留有效内容的最小幂等编辑，不因格式偏好或软预算覆盖全文。当前场景、dirty 文件清单、一次测试结果、分支、机器状态、本机绝对路径、秘密值和完整目录枚举不得进入长期规则。
- 只有稳定细则明显属于特定任务/路径且会挤占根文件时，才在 `.gameagent/rules` 创建普通 UTF-8 Markdown。根 `AGENTS.md` 必须为每份辅助规则写明触发任务或路径、项目相对路径和“采取修改动作前先读取”。
- `.gameagent/rules` 不会自动加载或自动注入上下文；它只通过根文件的显式路由被智能体主动读取。独立子项目优先沿用最近的嵌套 `AGENTS.md` 和 README，不复制全部规则。

## 5. 紧凑写入护栏

- 开始前检查工作区状态；现有脏改属于用户，不覆盖、回滚、格式化或清理无关改动。不读取、记录或回显 API Key、token、密码、证书或 `.env` 值。
- 写入前对根文件、`.gameagent/rules` 和目标文件检查 `lstat`/真实路径、权限和 symlink 身份。Git 项目用 `git check-ignore -v --no-index` 与 `git ls-files`/status 检查 ignore/trackability；非 Git 项目标记为不适用。
- 缺失的 `.gameagent/rules` 被 ignore 时，不创建不可追踪文件，不自动修改 `.gitignore`；把必要规则留在根文件，并只报告针对规则目录的精确建议。路径是 symlink、特殊节点、类型冲突或越出项目根时不得写入。
- 多文件更新不能承诺整体原子提交：先写并完整复读每个辅助规则，全部验证通过后才最后最小编辑根 `AGENTS.md`，禁止先写断链路由。
- 失败后读取结构化错误与现场 partial state，再尝试缩小范围、修正参数、继续 cursor 或改用最小 Edit 等有实质差异的安全恢复。不得自动删除或回滚用户文件；安全路径耗尽时逐项报告已成功、失败、未尝试路径和真实 Undo 能力。

## 6. 写后验证与报告

完整复读根文件和所有路由目标，并检查：

- 固定 Cocos 核心是否完整，项目特有规则是否均有证据，未知事实是否被省略；
- 人工/managed 内容是否保留，重复/冲突/瞬态/秘密/本机路径是否禁入；
- 路由触发条件、相对路径、行动前阅读指令、链接和目标文件是否一致；
- 文件身份、ignore/trackability、diff/status、约 100 行软预算、真实命令和幂等性。

最终报告列出项目类型与依据、读取的高价值证据、根文件的零写入/创建/最小更新、每份辅助规则及路由、项目特有规则来源、省略或待确认项、实际自动化、partial state 和未执行项。工具返回 `ok` 只说明该次调用，不能替代持久化文件、诊断、Git 事实或 Creator 验证；未运行的真实 Provider、Creator Dashboard/GUI、保存重开、人工质量审查和目标平台构建必须明确标为未验证。
