# Game Agent · 中文使用指南

**在 Cocos Creator 里，把游戏想法一步步做出来。**

Game Agent 是一款面向 Cocos Creator 的 AI 开发助手。你可以用中文描述需求，让它阅读项目、编写脚本、搭建场景、调整组件、生成图片，并通过游戏预览检查结果。项目资料、编辑器操作和对话都集中在同一个工作区，方便你边看、边改、边验证。

适用于 **Cocos Creator 3.7.0 及以上版本**。这份指南从第一次打开插件开始，介绍日常开发最常用的操作。

![Game Agent 在真实 Cocos Creator 中的工作区：左侧为项目资源，中间为编辑区域，右侧为对话面板](packages://game-agent/static/user-guide/01-workspace.jpg)

## 1. 安装与授权

### 使用前准备

- 安装 Cocos Dashboard，以及 Creator 3.7.0 或更高版本。
- 准备一个可以正常打开的 Creator 项目。初次体验可以新建空项目。
- 使用购买 Game Agent 的 Cocos 账号登录 Dashboard / Creator。
- 准备一种可用的语言模型接入方式：模型服务的 API Key，或插件支持的 ChatGPT/Codex 账号授权。

**插件授权和模型服务分别管理。** 购买插件后，仍需自行准备模型服务的可用额度；语言模型、生图、联网搜索等服务的费用由对应服务商计算。

### 安装插件

通过 [Cocos 商城 Game Agent 页面](https://store.cocos.com/app/detail/9114) 获取插件，并按商城 / Dashboard 的提示安装到目标项目。

如果你拿到的是发布 ZIP，可以手动安装：

1. 完全关闭目标项目的 Creator 编辑器。
2. 解压 ZIP，把里面的 `game_agent` 文件夹放到项目的 `extensions` 目录。没有 `extensions` 时可自行创建。
3. 检查下方目录结构。`package.json` 应直接位于 `game_agent` 文件夹内。
4. 回到 **Cocos Dashboard**，打开该项目。
5. 在 Creator 的 **扩展 → 扩展管理器** 中确认 Game Agent 已启用。
6. 点击 **扩展 → 打开 Game Agent**。资产面板的入口是 **扩展 → 打开 Game Agent 资产管理**。

```text
你的项目/
├── assets/
├── package.json
└── extensions/
    └── game_agent/
        ├── package.json
        ├── README.zh.md
        ├── dist/
        └── static/
```

更新插件时，同样先退出 Creator，再替换插件文件夹，最后通过 Dashboard 重新打开项目。避免同时安装两份 Game Agent。

### 首次授权

插件会检查当前 Cocos 登录账号的购买状态。如果出现授权提示，按提示登录购买账号，然后点击 **重新检测**。刚购买的订单需要同步时间；页面提示稍后重试时，等待后再检测即可。

如果提示网络异常，先检查网络连接，再重新检测。授权通过后，聊天面板会正常显示。

## 2. 接入模型

**先接入一个语言模型，就可以开始对话。** 生图、搜索和 MCP 可在需要时再配置。

打开 Creator 的 **项目 → 项目设置**，在左侧找到 **game-agent** 分组。这里保存服务接入信息；聊天面板右上角的齿轮用于调整日常使用设置。

![项目设置中的官方语言模型接入页面](packages://game-agent/static/user-guide/02-model-settings.jpg)

*图 2 · 在“项目设置 → game-agent”中接入服务。图中为空配置示例。*

### 方式 A：内置服务的 API Key

**跟着视频操作：** [API Key 接入视频教程 · 哔哩哔哩](https://www.bilibili.com/video/BV1yQ8x6tENJ/)。第一次配置可以先看视频，再对照下面的步骤填写。

1. 在你选用的模型服务平台创建 API Key，并确认账号有可用额度。
2. 打开 **官方语言模型接入**。
3. 将 Key 填到对应服务商的输入框，例如 DeepSeek、OpenAI、Anthropic、Google AI、xAI、Mistral、阿里云通义、Moonshot AI 或智谱 BigModel。
4. 完成输入后点击页面空白处，再回到 Game Agent 面板。
5. 点击输入框下方的模型下拉框，选择一个可用模型。

只需填写你使用的服务，无需填满所有输入框。模型列表显示的是当前已配置的服务；实际能否调用，还取决于账号权限、额度与网络。

### 方式 B：ChatGPT/Codex 账号授权

在 **官方语言模型接入** 中找到 **ChatGPT/Codex 授权**，点击后在浏览器完成登录与授权。成功后返回 Creator，从模型下拉框选择对应模型。

如果页面显示需要重新授权，使用该页面的重新授权操作。具体模型可用性和额度以账号实际状态为准；生图功能仍需单独配置图片服务。

### 方式 C：自定义模型服务

如果你的服务商提供兼容接口，打开 **自定义语言模型接入 1 / 2 / 3**。每个连接最多可配置三个模型。

| 配置内容 | 如何填写 |
| --- | --- |
| 连接启用与显示名称 | 启用连接，填写便于辨认的名称 |
| API 协议 | 按服务商文档选择 OpenAI Chat、OpenAI Responses 或 Anthropic Messages |
| Base URL | 填写服务商给出的接口基础地址，注意是否已包含 `/v1` 等前缀 |
| 鉴权与 API Key | 按服务商要求填写；有额外请求头时再配置 |
| 模型启用与模型 ID | 启用需要的模型槽位，填写服务商实际接受的模型 ID |
| 模型能力与上下文长度 | 按实际能力填写；需要看图时，确认该模型支持图片输入 |

填好后点击该模型的 **测试连接**，再回到聊天面板选择模型。测试会发送一次实际模型请求，可能消耗少量额度。测试失败时，优先核对协议、地址、模型 ID、Key 和账户额度。

只连接你信任的服务。API Key 保存在项目的 `settings/v2/packages/game-agent.json` 中，请将这个文件排除在代码提交和公开分享之外；不要把 Key 粘贴到聊天消息中。

### 选择主力模型与辅助模型

打开 **Game Agent 右上角齿轮 → 基础**：

- **主力模型**：处理主要对话与开发任务，优先选择代码能力强、工具调用稳定、能理解项目结构的模型。经常根据截图调整 UI 时，还应支持视觉理解。
- **辅助模型**：用于审批复核、子智能体等辅助任务，优先选择**价格便宜、上下文容量大**的模型，同时保证工具调用与指令遵循可靠。这样能降低持续开发中的辅助调用成本。

![Game Agent 的基础设置与功能标签页](packages://game-agent/static/user-guide/03-basic-settings.jpg)

*图 3 · 日常配置集中在面板设置中，模型密钥在 Creator 项目设置中填写。*

### 怎样为任务选择模型

先确认模型能完成任务，再比较价格与速度。模型是否适用，重点看下面几项：

| 能力 | 对你有什么影响 | 选择建议 |
| --- | --- | --- |
| 代码与工具调用 | 能否阅读项目、正确调用编辑器工具、完成修改与验证 | 开发任务优先选择支持工具调用且表现稳定的模型 |
| 上下文容量 | 一次能容纳多少历史对话、代码、工具结果和图片信息 | 日常项目建议使用 256K～512K，按实际任务规模选择 |
| 视觉理解 | 能否理解截图、布局参考、图标与游戏画面 | 看图分析和 UI 任务选择支持图片输入的模型 |
| 推理能力 | 处理复杂逻辑、疑难报错和多步骤任务的能力 | 复杂任务使用支持推理的模型，再按需要调整强度 |
| 价格与速度 | 长时间开发的费用，以及每轮等待时间 | 主力模型重视完成质量；辅助模型重视低价、大上下文与响应效率 |

刚开始可以用同一个小任务比较候选模型，例如“读取玩家控制脚本，解释移动逻辑，再完成一个小修改并验证”。观察它是否找对文件、正确使用工具、解释清楚结果，并结合服务商账单比较实际开销。

### 上下文是什么，应该填多大

上下文是模型一次处理信息的容量。历史消息、项目代码、工具返回、图片信息和生成回答都需要使用这部分容量。Token 是模型计量文本等输入输出的单位，与汉字数或文件大小没有固定的一一对应关系。

**推荐范围为 256K～512K。** 普通功能开发、脚本修改可以先用 **256K**；经常阅读多个模块、处理较长会话或大量工具结果时，可以选择 **512K**。辅助模型同样优先考虑这个范围内价格较低的型号。

在自定义接入中这样设置：

1. 打开 **项目设置 → game-agent → 自定义语言模型接入 1 / 2 / 3**。
2. 找到正在使用的模型槽位。
3. 在 **上下文长度（K）** 中直接填写 **256** 或 **512**，然后离开输入框完成保存。
4. 回到 Game Agent，重新选择该模型，并通过上下文分析检查当前容量与用量。

当前输入框以 **K** 为单位，`1K = 1024 tokens`；允许填写的范围为 128～1024。**填写前确认服务商的真实上限**：模型只支持 256K 时就填 256；只支持 128K 时填 128。填大数值不会扩展远端模型的实际能力，反而可能让请求超出上限。

内置模型与 ChatGPT/Codex 模型的上下文信息由插件目录管理，直接选择合适的型号即可。输入区的上下文圆形指示器用于查看分析；自定义模型的容量在项目设置中修改。

![自定义模型设置中的上下文长度 K、图片输入、思考能力和推理档位](packages://game-agent/static/user-guide/07-model-capabilities.jpg)

*模型参数示例 · “上下文长度（K）”填 256，表示 256K。图片输入和推理能力按服务商实际支持情况配置。*

容量增大后，会话可能保留更多信息，实际发送的内容也可能增加。费用以服务商实际计费为准；独立任务及时新建会话，可以减少无关历史占用。

### 推理强度怎么选

选择支持可调推理强度的模型后，点击输入框下方的 **思考深度**，选择当前任务需要的档位。不同服务商的档位名称和数量会有差异。

| 任务 | 建议起点 |
| --- | --- |
| 简短问答、解释一段代码、修改少量文案 | 低 |
| 日常功能开发、常规场景修改、一般报错分析 | 中 |
| 多文件问题定位、复杂逻辑、架构分析 | 高 |
| 高档仍无法解决的疑难任务 | 按需尝试超高或最大，并留意耗时与额度 |

**日常先用“中”，遇到难题再提高。** 较高档位通常需要更多推理时间和计算预算，实际费用取决于服务商。清晰的需求、准确的文件引用和可验证的目标，同样会影响结果质量。

![聊天输入区中当前模型支持的思考深度选项](packages://game-agent/static/user-guide/08-reasoning-level.jpg)

*推理强度示例 · 此模型提供低、中、高、超高、最大五档；其他模型以实际菜单为准。*

自定义模型还需要先配置 **思考能力** 和 **推理档位（逗号分隔）**。例如，服务商明确支持 `low,medium,high` 时才填写这些值；按它实际接受的名称填写，避免照搬其他模型的档位。未提供可调档位的模型，聊天区不会显示该选择器。

### 视觉理解与图片输入

视觉理解用于分析你提供的图片，例如读取报错截图、检查 UI 布局、比较参考图与游戏画面。图片生成用于创作新的素材，通过生图智能体和图片服务使用。

做看图任务前，完成三项检查：

1. **模型支持看图**：从模型能力说明或服务商文档确认支持图片输入。
2. **接入支持传图**：自定义模型要启用 **图片输入**，并确认对应接口能传递图片。勾选该项本身不会为纯文本模型增加视觉能力。
3. **告诉 AI 看什么**：发送前确认附件缩略图，并说明需要关注的区域、目标尺寸和期望效果。

文字很小或画面复杂时，补充关键区域的清晰截图，并把必须准确的文字直接写在消息里。AI 看图后，仍应在 Creator 中检查真实布局与交互结果。

## 3. 第一次使用

建议先完成一次只读对话，再尝试一个小改动。这样可以快速确认模型、项目读取和编辑器操作都能正常工作。

### 第一步：让 AI 认识项目

在输入区下方选择 **探讨** 模式；面板较窄时，打开 **更多 → 模式 → 探讨**。复制下面这段话并发送：

```text
请阅读当前 Cocos Creator 项目，告诉我：
1. 使用的 Creator 版本和主要目录。
2. 已有哪些场景与游戏脚本。
3. 从哪里开始阅读最合适。
本轮只分析，不修改文件或场景。
```

你会看到回复和工具调用卡片。展开卡片可以查看它读取了什么，以及操作是否成功。如果模型下拉框仍显示“未配置模型”，先回到上一节完成接入。

### 第二步：建立项目规范

切换到 **工作** 模式。在输入框输入 `/`，从候选项中选择 **项目初始化**，然后发送。

这个命令会让 AI 检查普通游戏项目，并创建或完善项目根目录的 `AGENTS.md`。它用来记录项目结构、开发约定和验证方式，帮助后续任务保持一致。已有规范时会先阅读并按需更新；执行中的写入操作仍遵循审批设置。

### 第三步：做一个看得见的小改动

在一个练习项目中打开场景，保持 **工作** 模式，使用 **手动审批**，发送：

```text
请检查当前场景，创建一个居中的“开始游戏”按钮。
如果已有合适的 Canvas，请复用它。
按钮大小为 240×80，文字为白色，背景为蓝色。
暂时不绑定点击事件。完成后说明新增了哪些节点和组件，
并读取结果，确认尺寸、位置与文字是否正确。
```

出现审批卡片时，先看清操作对象和内容，再决定允许或拒绝。完成后在层级管理器选中按钮，检查属性检查器中的组件、尺寸和文字。

### 第四步：保存并验证

保存场景，再点击 Creator 的预览按钮查看实际效果。发现问题时，把现象说具体：

```text
按钮在编辑器里居中，但竖屏预览时偏到了右侧。
请检查 Canvas、父节点尺寸和 Widget，修正后再次预览。
```

每完成一个小目标就保存一次。正式项目建议配合 Git 提交，便于比较和恢复修改。

## 4. 看懂聊天面板

### 常用操作速查

| 位置 / 操作 | 用途 |
| --- | --- |
| 顶部加号 | 新建会话，开始一个独立任务 |
| 历史会话 | 找回之前的对话并继续 |
| 分享会话 | 导出 / 导入会话，可选携带项目文件与日志 |
| 问题反馈 | 查看反馈渠道 |
| 齿轮 | 设置模型、工具、技能、智能体、工作流、上下文与 MCP |
| 输入框中的 `/` | 选择命令、技能、智能体或工作流 |
| 输入框中的 `@` | 搜索并引用项目文件、节点或可用资产 |
| 输入框下方的加号 | 打开附件等输入操作 |
| 模型下拉框 | 为当前任务选择语言模型 |
| 思考深度 | 在模型支持时调整推理强度 |
| 上下文圆形指示器 | 查看当前上下文用量与分析 |
| 发送 / 停止 | 提交需求，或停止当前生成与执行 |

宽面板直接展示部分选项；窄面板会将 **模式** 与 **审批方式** 放入 **更多**。

### 探讨与工作

**探讨** 适合了解项目、讨论设计、分析报错。它可以读取信息并给出建议，不能执行写入修改。

**工作** 适合编写脚本、调整场景和执行验证。它可以使用已授权工具，遇到需要审批的操作时按当前审批方式处理。

### 工具权限与操作审批

在 **设置 → 工具** 中，可以按工具选择 **关闭、审批、同意、自动**。关闭会隐藏该工具；审批要求每次确认；同意允许直接执行；自动按操作风险判断是否需要确认。需要审批的调用会显示操作卡片，确认后才继续。

![工具权限设置页面](packages://game-agent/static/user-guide/04-tool-permissions.jpg)

*图 4 · 按工具设置权限。首次使用建议保留手动审批，逐步熟悉各项操作。*

**手动审批** 由你逐次确认；**帮我审批** 由辅助模型复核，判断可放行时自动继续，其余情况仍交给你。辅助复核可能增加模型调用费用。

停止任务后，已经完成的文件或场景修改会保留。需要恢复时，检查 Creator 撤销记录或使用项目版本管理。

### 任务运行中继续补充要求

执行过程中可以继续输入补充说明，待处理消息会显示在输入区附近。例如“保留现在的配色，只调整间距”。需要立刻改变方向时，先停止当前任务，再给出新的完整要求。

## 5. 给 AI 足够的上下文

### 引用具体对象

输入 `@` 后搜索文件、节点或资产，从候选项中选中，引用会留在输入框里。配合一句目标说明，通常比“帮我改一下那个按钮”更容易得到准确结果。

```text
请检查我引用的脚本，找出按钮点击后没有响应的原因。
先说明事件绑定和节点状态，再提出最小修改方案。
```

### 附上截图或参考图

可以将剪贴板中的图片粘贴到输入框，发送前检查缩略图，移除不需要的图片。需要模型理解图片时，选择支持图片输入的语言模型。

告诉 AI 图片的作用：是报错截图、布局参考，还是要检查的游戏画面；再说明希望它关注的区域。

```text
这是当前游戏的结算界面截图。
请重点检查底部按钮间距和标题位置，给出适配 720×1280 竖屏的修改建议。
保留现有文案与美术风格。
```

### 写清目标、范围和完成标准

一个好用的需求通常包含四件事：**要做什么、改哪里、保留什么、怎样算完成**。

```text
目标：给玩家增加受击闪烁效果。
范围：玩家控制脚本和玩家 Prefab。
要求：受击后闪烁 3 次，每次 0.1 秒；保留现有移动和攻击逻辑。
验证：运行预览，连续受击时不叠加多个闪烁任务。
完成后列出修改文件，以及实际做过的检查。
```

大型需求建议拆成“先梳理项目 → 确认方案 → 实现一部分 → 预览检查”。换到新的独立任务时，新建会话，并重新引用必要文件。

## 6. 技能与智能体

### 技能：为特定任务提供方法与知识

技能会为 AI 提供某类任务的知识和操作步骤。内置技能覆盖 Cocos 文档查询、场景搭建、2D 精灵和 2D 地图资产等方向。

在 **设置 → 技能** 中查看技能说明和调用方式；在输入框输入 `/` 可显式选择可用技能。自动调用模式下，AI 也会根据任务内容选择相关技能。

| 任务 | 可以这样描述 |
| --- | --- |
| 查 Cocos 用法 | “根据当前 Creator 版本，查询 Button 点击事件的正确绑定方式，并结合我的项目解释。” |
| 搭建场景 | “请参考附图搭建主菜单，先整理节点层级、布局关系和需要的资源。” |
| 制作 2D 精灵 | “制作一套俯视角角色行走帧，说明方向、帧数与导入方式，先确认规格。” |
| 制作地图资产 | “为横版平台游戏制作可拼接地块，先确定瓦片尺寸和边缘连接规则。” |

### 智能体：把任务交给合适的角色

**设置 → 智能体** 中可以查看和配置内置角色，也可以创建自定义智能体。不同角色承担调研、代码、执行、测试或生图等工作。

在输入框通过 `/` 选择本次需要的智能体，再描述它的任务。角色的模型、启用状态和工具权限会影响实际执行能力。

新手可以先使用默认主智能体完成小任务；当任务需要分工时，再选择专用角色。多个角色运行会增加模型调用和上下文消耗。

## 7. 图片与工作流

### 生成游戏图片

1. 在 **项目设置 → game-agent → 生图模型接入** 配置图片服务的凭证。内置入口包含 OpenRouter、ModelSell、阿里云百炼；百炼还需填写 Workspace ID。
2. 如使用兼容的图片中转服务，在 **自定义生图模型接入** 中按服务说明配置。当前自定义接入面向 GPT Image 2，模型别名背后的实际模型应与其一致。
3. 打开 **设置 → 智能体**，为生图智能体选择可用图片模型。
4. 在输入框选择生图智能体，说明用途、风格、尺寸、背景与需要保留的元素。
5. 生成完成后，在 **Game Agent 资产管理** 中预览和导入。

```text
为卡通冒险游戏生成一个木质宝箱图标，正面略俯视。
单个主体居中，轮廓清楚，透明背景，四周留出空白。
不要文字，不要阴影底板，用于背包物品栏。
```

图片服务的 **测试连接** 会真实生成一张测试图片，可能产生费用。语言模型的 Key 与图片服务的 Key 分开配置。

### 工作流：按固定步骤完成一类任务

工作流把输入、模型调用、脚本处理和结果输出连接成固定流程。它需要你显式选择并启动。

打开 **设置 → 工作流**，查看流程是否启用，以及是否需要准备依赖。回到输入框输入 `/`，选择工作流后发送。初次使用可只选择工作流，随后按运行卡片填写表单。

![工作流环境准备与运行资源设置](packages://game-agent/static/user-guide/05-workflows.jpg)

*图 5 · 工作流的环境准备与运行资源设置。向下滚动可以查看流程目录和状态。*

一次提交只选择一个工作流。参考图应按该工作流的输入表单选择；不要同时混选技能、智能体或普通聊天图片附件。

### 示例：生成可编辑的 UI 预制体

内置 **UI 生图到 Prefab** 工作流面向游戏 UI 制作：收集需求，生成与分析分层图片，整理素材，再输出可在 Creator 中继续编辑的预制体。

启动后，按卡片提示填写界面描述、目标尺寸、必要元素、精确文字、参考图及输出位置等信息。可以从下面的需求开始：

```text
制作一张 720×1280 的竖屏冒险游戏主菜单。
风格：温暖、明亮、手绘卡通。
必须元素：游戏标题、开始游戏按钮、设置按钮、底部版本文字。
精确文字：森林冒险、开始游戏、设置、v1.0。
标题置顶，开始游戏按钮位于画面下半部中央。
普通文字需要在 Creator 中继续编辑。
```

首次运行时可能需要下载并准备 Python 或脚本依赖。根据卡片与工作流设置完成准备，保持网络可用，等待状态更新后继续。

流程中的四象限图片分别承担完整效果、背景、UI 元素和普通文字层。完成后，普通文字会尽量落实为可编辑的 **Label**，图片由 **Sprite** 承载，按钮可包含基础 **Button** 组件。按钮点击事件与业务逻辑需要后续添加。

输出后，按以下顺序检查：

1. 打开运行卡片中的预览和结果，阅读警告或待检查项。
2. 在 Creator 资源管理器找到输出的 Prefab，拖入测试场景。
3. 检查层级、文字、按钮、透明边缘和资源引用。
4. 保存场景，在目标宽高比下运行预览，再调整细节。

若结果标为 **仅供检查 / review_only**，按报告处理未通过的项目，本轮不会发布到项目。出现警告的结果也应人工检查画面。

启用图片质量纠偏的新版流程，在图片校验未通过时最多追加三次生图请求；卡片会显示纠偏进度。这会增加耗时和费用，具体行为以该次运行卡片与流程版本为准。

需要续跑时，使用运行卡片实际提供的检查点操作。插件更新后，新流程从新运行开始；历史运行保留其原有定义。

## 8. 资产与会话管理

### 管理生成的素材

通过 **扩展 → 打开 Game Agent 资产管理** 打开独立面板。它可以与控制台放在一起，集中查看生成的图片与其他受管资产。

按会话、收藏和更多筛选条件查找资源，先预览，再按需要导入项目。导入后，在 Creator 资源管理器确认文件和引用；项目内移动、重命名资源时，优先通过 Creator 操作。

资产拥有独立生命周期，删除会话不会自动删除其产出。删除资产前留意界面是否提供联动删除项目资源的选项，确认影响范围后再操作。

### 保存和继续对话

会话与日志保存在当前项目 `.gameagent/.data/session`，更新插件安装目录不会删除这些数据。点击顶部 **历史会话** 可以切换。长时间开发建议按任务划分会话，例如“主菜单”“玩家移动”“战斗结算”。

本次采用全新的存储布局，不自动读取或迁移旧版会话。用户自定义的智能体、技能、工作流、命令与规则保留在 `.gameagent` 顶层，插件内部资料集中在 `.gameagent/.data`。建议将 `.gameagent/.data/` 加入项目 Git 忽略规则；插件不会替你修改该配置。

输入区的上下文指示器显示当前用量，点击可打开分析。上下文很大、任务方向已经变化，或顶部出现新建会话提示时，先让 AI 整理进度和关键文件，再开启新会话。

### 导出与导入

点击顶部 **分享会话**：

1. 在导出页选择需要的会话。
2. 按需勾选项目文件与日志；项目文件默认不选。
3. 导出 ZIP，检查内容后再交给协作者。
4. 接收方通过同一窗口的导入页选择 ZIP，阅读导入范围和冲突提示。

![会话分享窗口中的导出与导入入口](packages://game-agent/static/user-guide/06-session-sharing.jpg)

*图 6 · 分享前确认会话、项目文件和日志的选择范围。*

导入会写入目标项目，应先备份。会话正文、附件和项目文件可能含有业务资料，分享前请检查。导出的会话无法自动代替接收方的模型账号、插件授权或本地运行环境。

## 9. 按需开启的进阶能力

| 能力 | 入口 | 使用要点 |
| --- | --- | --- |
| Web 搜索 | 项目设置 → game-agent → Web 搜索接入 | 配置 Tavily Key，适合查询联网资料；服务额度由 Tavily 管理 |
| 游戏预览测试 | 项目设置 → game-agent → 游戏预览测试 | 按提示准备预览环境，再让 AI 启动预览、观察画面和检查日志 |
| MCP | Game Agent 设置 → MCP → 设置 MCP | 连接外部工具服务；按服务要求配置连接、授权与工具权限 |
| 自定义命令 | Game Agent 设置 → 命令 | 将常用需求保存为命令，再通过 `/` 选择 |
| 工作流资源清理 | Game Agent 设置 → 工作流 | 查看依赖与缓存占用，使用界面提供的清理操作 |

浏览器自动化、脚本分析和 MCP 等能力可能需要额外的本机 Node.js 或浏览器环境。遇到依赖提示时，按具体功能页面给出的版本与路径要求准备；基础聊天可先单独使用。

## 10. 常见问题

### 从通用智能体调用 Creator（CLI 实施候选）

CLI 接入完成发行后，可在 **Game Agent 设置 → 基础 → 开放 CLI** 中选择常用智能体。插件检查外部 Node.js 22.20.0 或更新版本，再安装客户端与 `game-agent-cli` 技能；缺少 Node.js 时，Creator 原生弹框会提供官网入口。正式 npm 包名为 `@game-agent/cli`，采用 MIT 许可证，推荐版本为 `0.1.0`。当前候选尚未发布，不能据此视为已上架功能。

安装就绪后，从目标 Creator 项目目录运行 `game-agent --help` 和 `game-agent doctor --json`。通用智能体可直接调用 Creator 工具，也可用 `game-agent agent start --prompt-file task.txt --json` 委托 Game Agent。委托会话会显示在插件面板；审批和问答仍在面板完成。关闭命令行观察不会停止任务，取消需使用明确的取消命令。

预览前先在 Creator 中启动浏览器预览。检查工具结果中的状态、验证字段与部分失败项；截图下载成功不代表玩法已通过。详细命令、工具合同和恢复方式见随客户端安装的技能及离线帮助。关闭“开放 CLI”会撤销服务并收束当前外部任务，已经完成的编辑不会自动撤销。

### 扩展面板没有 Game Agent，或介绍仍为空

先确认插件已在扩展管理器启用，安装目录内存在 `package.json`。中文说明文件应位于同一层级，名称为 `README.zh.md`，`static/user-guide` 配图目录也要完整保留。

手动更新后完全退出 Creator，再通过 Dashboard 打开项目。检查是否有重复安装、嵌套文件夹或旧版本仍被加载。

### 填了 Key，模型列表仍然是空的

确认填写的是当前项目的设置，Key 放在了对应服务商字段。自定义接入还需启用连接和模型，并填写完整配置。完成后回到或重新聚焦 Game Agent；仍未刷新时关闭并重新打开面板。

### 模型可选，但请求失败

依次检查账户额度、模型使用权限、网络、API 协议和 Base URL。自定义连接可先执行“测试连接”。查看 Creator 控制台中的具体失败信息；连接测试的原始错误可能包含敏感内容，分享前先检查。

### AI 一直分析，没有修改项目

查看当前是否处于 **探讨** 模式，或某张审批卡片仍在等待。切换到 **工作**，明确要修改的内容，检查相关工具是否被设为“关闭”。

### 图片无法发送，或模型看不到图片

确认使用的是支持图片输入的模型，并在发送前看到了附件缩略图。自定义模型的图片能力设置要与服务实际能力一致；普通聊天附件与工作流参考图使用各自的输入入口。

### 工作流显示“首次运行需准备”或“依赖不可用”

打开工作流详情和运行卡片，查看缺少的是语言模型、生图模型还是脚本环境。按提示准备后刷新目录。环境下载失败时先处理网络或权限问题，再使用界面提供的继续操作。

### 生成的 UI 与参考图有差异

把问题限定到具体位置，例如“顶部数值遗漏”“按钮文字偏右”“透明边缘有底色”。检查运行报告和分层预览，再决定重新生成或在 Creator 中调整。图片模型输出、文字排版和最终游戏运行效果都需要实际检查。

### 已经购买，但仍提示未购买

核对 Creator 登录账号是否与购买账号一致。新订单按页面提示等待同步后重新检测；持续异常时，通过面板顶部 **问题反馈** 联系支持，并提供购买与错误信息的必要部分。

### 反馈问题时准备什么

- Game Agent 与 Creator 的版本、操作系统。
- 从哪个入口开始、做了什么、期望什么、实际发生什么。
- 相关截图、错误文字、会话或工作流结果。
- 能复现问题的最小步骤；需要项目文件时只提供必要范围。

请去掉 API Key、账号令牌和无关业务资料。问题反馈入口提供支持渠道，也可以从 [Game Agent 商城页面](https://store.cocos.com/app/detail/9114) 查看产品信息。
